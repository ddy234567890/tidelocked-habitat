# Teegarden b 행성 탐사 모델

2026-10-30 · v4.0 · 독립 프로토타입 · 작성자 검증 완료

행성에서 A·B·C를 누르면 카메라가 먼저 이동하고, 도착한 뒤 지형이 점으로 구성된다. 지역 간에는 카메라가 행성 표면을 따라 직접 이동한다. 전체 궤도 시점으로 돌아가는 동작은 ‘행성으로’를 누를 때만 실행한다.

## v4 변경

- 전환 순서: 카메라 이동(궤도 2.3초 / 지역 간 1.9초) → 정지 0.1초 → 홀로그램 구성 1.05초. 이동 중에는 도착 모델을 숨긴다. 구성 단계에서는 카메라 자세를 고정한다.
- 지역 이동: 출발 지형은 제자리에 두고 카메라의 위치·시선이 실제로 다음 지역까지 바뀐다. 이전 화면을 새 카메라에 붙여 놓는 v3의 화면 교체 방식을 제거했다. 이동 경로에만 희미한 3,600점 표면 가이드를 잠시 표시하고 완료 후 해제한다.
- 홀로그램: 화면 전체를 가로지르는 CSS 선을 없앴다. 모델 자체의 점 밝기와 고정된 점별 순서로 형태가 채워진다. 지역은 아래→위, 행성 복귀는 위→아래 방향을 유지한다.
- 일반 조작: 휠·터치 확대/축소·회전에는 추가 효과가 없다.
- 공통 PointsMaterial 한 개를 유지한다. 새 셰이더나 머티리얼을 추가하지 않았다. 흔들림 속성은 데이터만 제공하며 실제 흔들림은 재생하지 않는다.
- 조절 값: src/effects.js 위쪽의 ORBIT_TRAVEL_MS, SITE_TRAVEL_MS, ARRIVAL_HOLD_MS, ASSEMBLE_MS. 위치·구도는 src/navigation.js의 PIN_DISK와 LOCAL_VIEWS.

## 단계별 선지와 에셋 배치 (2026-10-31)

- 메인 게임의 선지 체계(src/data/choices/week1.json, composer.js 의 requires·resolve 규칙)를 이 시안으로 옮겼다. 데이터는 src/choices.json, 규칙은 src/choices.js, 모델 → 점 변환은 src/placement.js.
- 1단계 지대(아래 A·B·C 카드) → 지역에 도착하면 2단계 거주 방식 → 하나 고르면 3단계 산소 생성 방식이 열린다. 앞 단계를 바꾸면 뒤 단계 선택은 지운다. 기존 화면 구성은 그대로 두고, 카드 줄 위에 단계 이름만 붙였다.
- 자리는 이 시안의 지형 단위다. [x, z] 만 주면 높이를 그 자리 바닥(A·C 지표, B 동굴 바닥)에 맞추고, crest 는 C 의 굽은 마루에서 잰다.
- 모델 점 색은 메인 게임과 같은 toneColors 규칙(src/palette.js): 밝기만 쓰고 파랑 단계, 가장 밝은 약 4.5% 크림, 모서리 강조. 머티리얼은 그대로 하나.
- B '동굴 통째 밀폐'는 상자 대신 그 자리 동굴 벽의 실제 테두리를 따라 막는다(buildCaveSeal): 입구 쪽으로 볼록한 막, 테두리를 따르는 테, 아치형 기밀문. 입구 아래 통로와 안쪽 좁은 목 두 곳.
- 모델 15개는 메인 게임 public/models 에서 src/models 로 복사했다. 출처·라이선스는 저장소 루트 ASSETS.md(모두 CC0, inflatable.glb 는 팀 자체 제작 scripts/make-inflatable-model.mjs). 독립 HTML에는 데이터 주소로 들어간다.
- 거주 방식 선지를 누르면 카메라가 그 모듈 점의 범위로 1.4초 동안 다가간 뒤 오른쪽으로 천천히 돈다(ORBIT_SPEED 0.25, 약 4분에 한 바퀴). 산소 선지를 누르면 그 장치로, 산소 생성 방식을 결정하면 주거와 산소 장치를 함께 담도록 다시 맞춘다. 비스듬히 28°(FOCUS_ELEVATION) 위에서 본다. 지역에 도착했을 때는 움직이지 않는다. 별·지형은 고정이고 카메라만 움직인다. 용암동굴은 안에서 돌 수 없어 전체 보기로 나온다.
- 지대(1단계) 카드는 눌러서 둘러볼 수 있고, '지대 결정'을 눌러야 거주 방식이 열린다. 각 단계의 '결정' 버튼을 누르면 그 단계 카드 줄은 접히고 다음 단계가 열린다. 결정한 항목은 한 줄 요약으로만 남는다.
- 에셋 점은 개수를 정하지 않고 모델 겉넓이에 맞춰 뽑은 뒤, 0.062 칸마다 하나만 남겨 고르게 편다(placement.js POINT_SPACING). 색은 toneColors 뒤 모듈 0.74, 오버레이 0.66 배로 어둡게 해 겹친 곳이 하얗게 넘치지 않는다. 레이어마다 choices.json 의 spacing·gain 으로 바꾼다(탑형 집 0.07·0.5: 높은 탑이 불투명해 보이지 않게).
- B 동굴 속 모듈: 큰 방 바닥을 따라 거주 캡슐(house-long) – 연결 통로(tube-connector) – 중앙 허브(base-large) – 통로 – 캡슐로 이어지고, 작은 방에 작은 모듈 묶음(space-base-modules). 큰 방 기둥은 뒷벽 쪽으로 옮겼다.
- 메인 게임의 흐름 점(flows)과 숨겨진 선지(C3 얼음 옆 기지), stats 는 아직 옮기지 않았다.

## 계승한 지형과 화면

- 30,000점 행성 및 지역 모델, mulberry32 고정 씨앗, 표면 기복 2.00×, 슬라이더 없는 화면.
- A는 현무암 평원·무뎌진 크레이터·중앙 평탄면을 가진다.
- B의 동굴 형태는 2026-10-31 메인 게임 용암동굴(src/scenes/locations/lavaTube.js)에서 옮겼다: 벌어진 입구에서 내려가는 통로, 넓은 방과 좁은 목, 거친 암벽과 밝은 모서리, 입구에서 드는 빛, 바위 더미, 기둥 두 개. 원본 단위를 3배로 키웠다. 이후 동굴 사진 참고로 다듬었다: 아치 입구 → 내려가는 통로 → 큰 방(바위 더미) → 좁고 높은 목 → 작은 방 → 목. 방은 더 깊어서 위쪽 암반 두께가 곳마다 다르고, 단면은 큰 굴곡과 판처럼 끊긴 천장을 가지며, 큰 방 뒤쪽 벽에서 옆 굴이 갈라진다. 내부 보기에는 양쪽 벽이 있고(비대칭), 전체/단면 보기에서는 z=0 반쪽 절개 모델을 사용한다. 무너질 위험의 주황 표시와 떨림은 사용자 요청으로 뺐다(RISK_U, RISK_THETA 삭제, shake 는 모두 0).
- C는 다섯 구간, 정상 높이 0·반폭 0.45, 얼음 골짜기 중심 4.8을 유지한다. 2026-10-31부터 이 값은 굽은 마루를 따라 잰다(ridgeFrame: u = x − ridgeCrest(z), 원점에서 마루 위치 0). 마루는 길이 방향으로 굽이치고, 완사면 쪽으로 곁가지 능선(SPUR)이 갈라져 내려간다. 곁가지 마루는 늘 원래 마루보다 낮다.
- A·B의 위치는 사용자 표시 이미지 기준으로 옮겼으며 C는 유지했다.
- 배경 별 720개와 항성의 세계 좌표는 고정이다. 카메라만 움직인다.
- 주변 지형(src/surroundings.js, 2026-10-31): A·B·C 지정 지형 바깥으로 같은 지표 함수를 이어 30,000점을 더 놓는다. 바깥으로 갈수록 점 간격이 넓어지고 어두워지며, 행성 곡률만큼 아래로 휜다. 용암동굴의 전체·단면 보기에서는 절개면 앞쪽을 비우고, 동굴 내부 보기에는 붙이지 않는다. 지정 지형 30,000점과 PLY 산출물은 그대로다.

## 자료와 표현 가정

입력은 Teegarden_b_행성정보_요약.docx, 사용자 지형 규칙, A·B 위치 표시 이미지 및 대화의 피드백이다. 최소질량 1.16 M⊕, 추정 반지름 1.04 R⊕, 공전주기 4.906일은 첨부 자료를 구분 표기했다. 문서의 과학적 주장 전체를 별도로 검증하지는 않았다.

v4 표현 참고: https://pin.it/64oUtN7Bw → https://kr.pinterest.com/pin/641551909469106646/ . 브라우저에서 Dan Neuenhaus의 차량 엑스레이/점·픽셀 표현을 확인했다. 영상이나 이미지를 프로젝트에 복제하지 않았으며, 표현 방식만 참고하고 기존 파랑·크림·주황 팔레트를 유지했다.

행성 지형·기후 분포·동굴·능선·탐사 위치는 실제 관측 지도가 아닌 설계 시나리오다. 지역 이동과 확대는 서로 다른 축척을 연결하는 연출이며 실제 m 단위나 지리 거리와 대응하지 않는다. 얼음 골짜기는 지정된 게임 설정이다.

A·B의 지도 위치는 사용자 이미지 구도를 우선하고, 각 지역의 기존 starDirection(def.star)은 유지했다. 새 전역 위치에서의 항성 고도와 지역의 9° 조명은 동일한 천문 좌표 해석이 아니다.

초기 원본 코드가 제공되지 않아 이 작업은 독립 시안이다. 실제 프로젝트 주거·산소 장치 좌표와의 정합성은 원본 확보 후 확인해야 한다.
